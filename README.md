# 포지션 사이즈 계산기

총자산, 손절 거리, 위험 비율로 진입 포지션의 **명목금액(USDT)** 을 계산하는 한국어 PWA입니다. Windows Chrome/Edge와 Android Chrome을 대상으로 합니다.

HTML, CSS, 순수 JavaScript ES Modules만 사용합니다. 빌드·패키지 설치·런타임 라이브러리가 필요하지 않습니다. 백엔드, 데이터베이스, 외부 API, 로그인, 기기 간 동기화는 없습니다. 레버리지와 증거금 계산은 포함하지 않습니다.

## 로컬 실행

저장소 루트에서 Python 정적 서버를 실행합니다. 이것은 로컬 확인용이며 배포 시 별도 서버가 필요하지 않습니다.

```sh
python -m http.server 8000
```

Linux에서 `python` 명령이 없으면 `python3 -m http.server 8000`을 사용합니다. 브라우저에서 **http://localhost:8000/** 을 엽니다. `file://`로 HTML을 직접 열면 모듈·서비스 워커·클립보드가 정상 동작하지 않습니다. PWA는 HTTPS 또는 localhost에서 확인하세요. 휴대폰의 일반 HTTP LAN 주소는 설치/서비스 워커 테스트에 적합하지 않습니다.

## 테스트

Node.js 22 이상에서, 추가 패키지 설치 없이 실행합니다.

```sh
node --test tests/*.test.mjs
```

계산식, 입력 검증, 소수 내림, 안전 범위, 저장 복원·손상·차단, 서비스 워커의 하위 경로 캐시·이전 버전 정리와 PNG 크기를 검사합니다. 서비스 워커 단위 테스트는 브라우저 API를 모의하므로 실제 설치 검증은 아래 절차로 별도 확인합니다.

구현 시 로컬 검증(2026-10-23): 단위 테스트 23개 통과. 임시 Chromium에서 예시 계산, 복사 성공·실패, 저장 복원·차단, 320/360/412/768px 화면, `/calculator/` 하위 경로의 오프라인 새로고침·저장·새 탭 재실행을 확인했습니다. 브라우저의 manifest 및 설치 조건 검사도 오류 없이 통과했습니다. Windows/Android 실제 기기 설치와 실제 GitHub Pages 배포는 아직 수행하지 않았습니다. 브라우저 검증 도구는 프로젝트 의존성에 포함하지 않았습니다.

브라우저 확인 순서:

1. `5300 / 2.6 / 1`을 입력해 **2,038.46 USDT / 53.00 USDT**를 확인합니다.
2. 복사 버튼을 누르고 텍스트 편집기에 붙여 넣어 `2038.46`만 들어가는지 확인합니다.
3. 공란, `0`, 음수, 문자, 위험 비율 `101`을 입력해 이전 결과가 사라지고 복사 버튼이 비활성화되는지 확인합니다.
4. 정상값을 입력하고 새로고침해 복원되는지 확인합니다. 저장소가 차단된 상태에서도 계산되는지 확인합니다.
5. `오프라인 사용 준비 완료`를 확인한 뒤 개발자 도구의 Network를 Offline으로 바꾸고 새로고침합니다. 계산과 새 입력값 저장·복원을 확인합니다.
6. PC와 Android에서 설치 후 앱을 완전히 종료하고 오프라인으로 다시 실행합니다. 작은 화면과 가로 화면, 확대 시에도 입력창과 금액을 읽을 수 있는지 확인합니다.

## 계산과 저장 정책

```text
예상 손절 손실 = 총자산 × (위험 비율 / 100)
진입 포지션 금액 = 예상 손절 손실 ÷ (손절 거리 / 100)
```

- 총자산·손절 거리는 0보다 큰 유한한 숫자, 위험 비율은 0 초과 100 이하입니다. 손절 거리에는 100 상한을 적용하지 않습니다.
- 입력 중 자동 교정이나 커서 이동은 하지 않습니다. 빈 입력은 안내를, 잘못된 입력은 한국어 오류를 표시하며 이전 계산 결과를 숨깁니다.
- 십진 문자열을 JavaScript 내장 `BigInt`의 정수 비율로 계산해 중간 반올림과 이진 소수 오차를 피합니다. 진입 금액은 소수 둘째 자리까지 **내림**, 손실 금액은 소수 둘째 자리까지 **반올림**합니다. 복사는 화면 금액에서 쉼표와 단위를 뺀 문자열입니다.
- 안전 범위는 두 결과 각각 센트 단위 `Number.MAX_SAFE_INTEGER`, 즉 **90,071,992,547,409.91 USDT 이하**로 보수적으로 제한합니다. 범위를 넘으면 결과를 표시하지 않습니다. 입력 자체가 JavaScript의 유한한 양수 범위를 벗어나도 거부합니다.
- 0.01 USDT보다 작은 진입 금액은 `0.00`과 작은 금액 안내를 표시합니다.
- 세 입력값은 `position-size-calculator:settings:v1` 키의 한 JSON 객체로 저장합니다. 필드별 마지막 정상값을 유지하며, 일시적인 공란·잘못된 값은 저장값을 덮어쓰지 않습니다. 다른 필드가 아직 비어 있어도 정상 입력은 저장합니다. 계산 범위를 초과하는 조합은 저장하지 않습니다.
- 손상되거나 잘못된 저장 객체는 전체 기본값(공란/공란/1)으로 복구합니다. 저장 실패 시 안내하고 계산은 계속 제공합니다.
- 입력값을 서버나 GitHub로 전송하지 않습니다. 저장은 기기·브라우저·프로필별로 독립적이며, 같은 브라우저의 같은 출처에서는 공유됩니다. 브라우저 데이터 삭제 시 저장값이 사라집니다.
- 수수료·슬리피지·체결 가격·펀딩비를 반영하지 않으며 실제 손실 상한을 보장하지 않습니다.

## GitHub Pages 배포

1. GitHub에서 공개 저장소를 만듭니다.
2. 이 프로젝트 파일을 `main` 브랜치에 올립니다. **`index.html`, `sw.js`, `manifest.webmanifest`는 저장소 루트**에 두고 `icons/` 경로도 유지합니다. 컴파일하거나 `npm install`을 실행할 필요가 없습니다.
3. 저장소 **Settings → Pages → Build and deployment → Source: Deploy from a branch**를 선택합니다.
4. **Branch: `main`, Folder: `/(root)`**를 선택하고 Save를 누릅니다.
5. 배포 완료 후 `https://<username>.github.io/<repository>/`에서 계산·복원·복사·PWA 설치를 확인합니다.

모든 앱 리소스와 manifest, 서비스 워커는 상대 경로를 사용하므로 저장소 하위 경로에서도 동작합니다. `.nojekyll`은 정적 파일을 그대로 게시하기 위한 파일입니다. 저장소 생성, 푸시, Pages 활성화는 사용자가 직접 수행합니다.

공식 안내: [GitHub Pages 게시 소스 설정](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

## 설치와 오프라인 사용

- **Windows Chrome/Edge:** 배포된 HTTPS 주소를 연 뒤 주소 표시줄의 설치 아이콘 또는 브라우저 메뉴의 앱 설치 항목을 선택합니다. 메뉴 이름은 브라우저 버전에 따라 다를 수 있습니다.
- **Android Chrome:** 배포 주소를 열고 브라우저 메뉴에서 앱 설치 또는 홈 화면에 추가를 선택합니다.
- 최초 온라인 로딩 후 서비스 워커 설치·활성화가 끝나야 오프라인 실행이 됩니다. 화면의 `오프라인 사용 준비 완료`로 확인합니다. 브라우저 저장소가 삭제되면 다시 온라인 접속이 필요합니다.
- PNG 아이콘은 192×192와 512×512이며 마스킹 안전 영역 안에 계산기 도형을 배치했습니다.

공식 안내: [PWA 설치 요구사항](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable), [오프라인 동작](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Offline_and_background_operation).

## 수정 배포와 캐시 갱신

1. HTML/CSS/JS/아이콘 등 앱 리소스를 바꾸면 **`sw.js`의 `VERSION`도 `v1` → `v2`처럼 올립니다.** 파일을 추가하거나 이름을 바꾸면 `FILES` 목록도 수정합니다.
2. 테스트 후 `main`에 푸시합니다. 온라인에서 앱을 다시 열면 브라우저가 새 서비스 워커를 확인하고 새 버전 파일을 캐시합니다.
3. 새 버전 준비 안내가 표시되면 이 계산기의 브라우저 탭과 설치 앱 창을 **모두 닫고 다시 엽니다.** 입력 도중 강제 새로고침하지 않도록 업데이트는 기존 창이 닫힐 때 적용합니다.
4. 활성화 시 해당 앱 범위의 이전 캐시만 삭제합니다. 다른 Pages 앱 캐시와 `localStorage` 입력값은 유지됩니다. 새 파일 다운로드가 실패하면 이전 워커를 유지합니다.
