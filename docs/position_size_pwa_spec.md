# 포지션 사이즈 계산기 PWA — 개발 기획서

> 이 문서는 VS Code에서 Codex에게 전달할 구현 명세다. 아래에 명시된 **현재 범위만 구현**하며, 임의로 기능을 확장하지 않는다.

## 1. 프로젝트 개요

- **앱 이름:** 포지션 사이즈 계산기 (Position Size Calculator)
- **목적:** 선물 거래 시 총자산, 진입가 대비 손절가까지의 가격 차이(%), 총자산 대비 허용 손실 비율(%)을 입력하면 해당 위험 한도에 맞는 **진입 포지션의 명목금액(USDT)** 을 즉시 계산한다.
- **대상 사용자:** 개인 사용자 1명
- **사용 환경:** Windows PC(Chrome/Edge) 및 Android(Chrome)
- **배포 방식:** GitHub Pages에 정적 파일을 게시하고 PWA로 설치
- **운영 비용:** 유료 서버·도메인·외부 API 없이 GitHub Pages 무료 범위에서 운영
- **서버/백엔드/DB:** 없음
- **데이터 저장:** 기기별 브라우저 `localStorage`만 이용. 인터넷 저장 및 기기 간 동기화 없음.
- **오프라인 사용:** 최초 정상 접속 및 서비스 워커 설치 후 오프라인에서 계산·저장·불러오기 가능

## 2. 개발 기술 및 원칙

- **HTML + CSS + 순수 JavaScript(ES Modules)** 로 구현한다.
- React, Vue, Flutter, Firebase 및 기타 프레임워크는 사용하지 않는다.
- 빌드 과정이나 외부 런타임 의존성 없이 GitHub Pages에서 바로 실행되는 단일 페이지 앱으로 만든다.
- 모바일과 PC 모두에서 하나의 반응형 레이아웃을 사용한다.
- 계산 로직을 화면 제어 로직과 분리해 단위 테스트가 가능하게 작성한다.
- 외부 CDN, 폰트 또는 인터넷 API에 의존하지 않아 오프라인에서도 동일하게 작동하도록 한다.
- UI 문구는 한국어로 작성하며 금액 단위는 **USDT**, 비율 단위는 **%** 로 표시한다.

## 3. 화면 및 기능 범위

### 3.1 입력 항목

| 항목 | 단위 | 최초 기본값 | 동작 |
|---|---|---|---|
| 총자산 | USDT | 공란 | 사용자가 직접 입력. 마지막 정상 입력값을 로컬 저장 |
| 손절 거리 | % | 공란 | 현재 진입가부터 손절가까지의 가격 차이 비율을 양수로 입력. 마지막 정상 입력값을 로컬 저장 |
| 위험 비율 | % | **1** | 손절 시 총자산에서 잃어도 되는 비율. 사용자가 변경 가능하며 마지막 정상 입력값을 로컬 저장 |

- 저장된 유효한 값이 있으면 앱 실행 시 복원하고, 없으면 위 기본값을 사용한다.
- 사용자는 `2.6`, `0.5` 등 소수 값을 입력할 수 있다.
- 입력이 변경되면 별도의 '계산' 버튼 없이 결과를 즉시 갱신한다.
- 입력 도중 일시적으로 빈 문자열이 되는 것은 허용하되, 그 상태에서는 계산 결과 대신 입력 안내를 표시한다.

### 3.2 계산 결과

1. **진입 포지션 금액(USDT):** 가장 크게 표시하는 주요 결과. 포지션의 **명목금액(notional)** 을 뜻하며 증거금이 아니다.
2. **예상 손절 손실(USDT):** 위험 비율에 의해 허용된 손실 금액.
3. **진입 금액 복사 버튼:** 계산된 진입 포지션 금액의 숫자만 클립보드에 복사한다. 복사 성공/실패에 대해 간단한 피드백을 제공한다.
4. 결과 옆 또는 하단에 `수수료·슬리피지 제외`라는 짧은 안내 문구를 표시한다.

**화면에서 제외할 항목:** 레버리지 입력, 증거금 계산 및 표시, Long/Short 선택, 현재가·손절가의 절대 가격 입력, 익절·손익비 계산.

### 3.3 화면 배치 예시

```text
┌────────────────────────────────┐
│       포지션 사이즈 계산기      │
│                                │
│  총자산 (USDT)                  │
│  [ 5300                      ]  │
│                                │
│  손절 거리 (%)    위험 비율 (%) │
│  [ 2.6       ]    [ 1        ] │
│                                │
│  ────────────────────────────  │
│  진입 포지션 금액               │
│       2,038.46 USDT            │
│                                │
│  예상 손절 손실                 │
│          53.00 USDT            │
│                                │
│   [ 진입 금액 복사 ]            │
│                                │
│  * 수수료·슬리피지 제외         │
└────────────────────────────────┘
```

- PC에서는 너무 넓어지지 않도록 전체 콘텐츠 폭을 약 400~480px 범위로 제한하고 화면 중앙에 배치한다.
- 안드로이드에서는 작은 화면에도 잘 맞게 표시한다. 화면 너비가 좁으면 두 비율 입력창을 세로로 배치해도 된다.
- 결과 금액은 숫자 구분 쉼표 및 소수점 둘째 자리까지 표시한다.
- 가독성이 좋은 단순한 스타일, 충분한 터치 영역, 명확한 포커스 표시를 사용한다.
- Android 숫자 키패드에서 소수점을 쉽게 입력할 수 있도록 `inputmode="decimal"` 등을 적절히 사용한다.
- 앱 UI는 추가 페이지·메뉴 없이 계산기 화면 하나로 구성한다.

## 4. 계산 규칙

입력값:

- `A`: 총자산(USDT)
- `D`: 손절 거리(%) — 예: 2.6
- `R`: 위험 비율(%) — 예: 1

계산식:

```text
예상 손절 손실(USDT) = A × (R / 100)
진입 포지션 금액(USDT) = 예상 손절 손실 ÷ (D / 100)
```

계산 예시:

```text
총자산 A          = 5,300 USDT
손절 거리 D       = 2.6%
위험 비율 R       = 1%

예상 손절 손실     = 5300 × 0.01 = 53.00 USDT
진입 포지션 금액  = 53 ÷ 0.026 = 2038.461538... USDT
화면 표시         = 2,038.46 USDT
```

- 계산은 입력된 퍼센트에 기반한다. `2.6`을 `260%`로 잘못 해석하지 않는다.
- 내부 계산에서는 불필요하게 중간값을 반올림하지 않는다.
- **진입 금액**은 소수점 둘째 자리에서 내림 처리하여 표시한다. 이렇게 하면 표시된 금액을 그대로 사용할 때 반올림 때문에 계획 손실을 미세하게 초과하는 일을 피할 수 있다. 예상 손절 손실은 소수 둘째 자리로 표시한다.
- 사용자에게 입력하는 손절 거리는 **진입가 대비 가격 변동률**이며, 포지션 금액은 레버리지를 곱하기 전후의 증거금이 아닌 **명목 포지션 규모**다.
- 실제 거래에서는 수수료, 슬리피지, 체결 가격 차이, 펀딩비 등에 따라 실제 손실액이 달라질 수 있다. **정확한 손실 상한을 보장하는 계산기가 아니다.**

## 5. 입력 검증과 예외 처리

- 총자산 `A`는 **0보다 큰 유한한 숫자**여야 한다.
- 손절 거리 `D`는 **0보다 큰 유한한 숫자**여야 한다. 특히 `0` 또는 공란에서 0으로 나누지 않는다.
- 위험 비율 `R`은 **0보다 크고 100 이하인 유한한 숫자**여야 한다.
- 숫자가 아닌 값, 음수, `Infinity`, `NaN` 등은 계산하지 않는다.
- 입력이 유효하지 않으면 오류 원인을 짧은 한국어 문구로 안내하고, `Infinity`, `NaN` 또는 오해를 부르는 이전 결과를 보여주지 않는다.
- 입력 중에는 값을 강제로 자동 교정하거나 커서를 옮기지 않는다.
- 결과가 JavaScript에서 안전하게 처리할 수 없는 크기이면 오류를 표시한다.
- `localStorage` 사용이 차단되거나 실패해도 계산 기능은 작동하도록 한다(저장만 생략).
- 클립보드 접근이 실패하면 사용자에게 복사 실패를 표시한다.

## 6. 로컬 데이터 저장

- `localStorage`를 사용하며 세 입력값(총자산, 손절 거리, 위험 비율)을 한 객체로 관리한다.
- 키 이름 예: `position-size-calculator:settings:v1`
- 값 예:

```json
{
  "assets": "5300",
  "stopDistancePercent": "2.6",
  "riskPercent": "1"
}
```

- 정상 입력값의 변경 시 로컬 데이터를 저장하고, 다시 실행하면 복원한다.
- 잘못된 입력 또는 손상된 저장값은 안전하게 무시하고 기본 상태로 돌아간다.
- 저장 데이터는 **PC와 휴대폰 각각 독립적**이다. 서로 자동 동기화하지 않는다.
- 브라우저/앱 데이터 삭제, 저장소 정리 등에 의해 저장값이 삭제될 수 있다.
- 앱에서 사용자 입력값을 서버, GitHub 저장소, 외부 분석 서비스로 전송하지 않는다.

## 7. PWA 및 오프라인 요구사항

- `manifest.webmanifest` 작성:
  - 앱 이름/짧은 이름, `start_url`, `scope`, `display: "standalone"`, 색상, 앱 아이콘 정의
  - 설치 인식에 필요한 **192×192, 512×512 PNG 아이콘**을 프로젝트에 포함
- `sw.js` 서비스 워커 작성:
  - 실행에 필요한 HTML/CSS/JS/manifest/icon 등을 캐시
  - 최초 온라인 접속 후 서비스 워커가 정상 설치·활성화된 상태에서 오프라인 실행 가능
  - 버전이 변경되면 이전 캐시를 정리하고 새 버전의 정적 파일을 사용할 수 있도록 구성
  - 계산 로직과 `localStorage` 데이터는 캐시 버전 갱신과 독립적으로 유지
- **GitHub Pages 프로젝트 경로**(예: `https://사용자명.github.io/저장소명/`)에서도 동작하도록 링크, 서비스 워커 범위, manifest 경로에 상대경로를 우선 사용한다.
- 앱 설치 후 Windows의 Chrome/Edge 및 Android의 Chrome에서 독립 실행 형태(브라우저 지원 범위 내)로 열리도록 한다.
- PWA 기능 테스트는 `file://`가 아니라 **HTTPS 또는 localhost**에서 진행한다.

## 8. GitHub Pages 배포

1. GitHub에 앱 전용 **공개(Public)** 저장소를 생성한다(무료 GitHub Pages 기준).
2. `index.html` 등 정적 파일을 저장소 루트에 배치하고 `main` 브랜치에 푸시한다.
3. 저장소 **Settings → Pages → Build and deployment → Source: Deploy from a branch**에서 `main` / `/(root)`를 선택해 배포한다.
4. 발급된 `https://<username>.github.io/<repository>/` 주소에서 계산기와 PWA 설치를 확인한다.
5. 수정 시 저장소에 푸시해 배포한다. 사용자가 설치한 PWA는 새 버전 리소스를 다시 받아 반영하도록 구현한다.

README에는 로컬 테스트, 배포, Windows/Android 설치 방법, 오프라인 사용 조건, 로컬 데이터의 기기별 분리를 간단히 설명한다.

## 9. 권장 파일 구성

```text
position-size-calculator/
├── index.html
├── styles.css
├── app.js                 # 화면 및 입력, 저장 처리
├── calculator.mjs          # 순수 계산 함수
├── manifest.webmanifest
├── sw.js
├── icons/
│   ├── icon-192.png
│   └── icon-512.png
├── tests/
│   └── calculator.test.mjs # 계산식 및 입력 검증 테스트
└── README.md
```

- 빌드 도구는 사용하지 않는다.
- 계산 로직 테스트는 가능하면 Node.js 내장 테스트 러너(`node --test`)를 사용해 추가 패키지 설치 없이 실행되도록 만든다.
- 원한다면 `python -m http.server 8000` 등 간단한 정적 서버로 로컬 구동 가능해야 한다.

## 10. 완료 기준(검수 체크리스트)

- [ ] 총자산과 손절 거리 입력, 위험 비율(기본 1%) 변경이 가능하다.
- [ ] 값이 바뀌면 진입 포지션 금액과 예상 손절 손실이 바로 갱신된다.
- [ ] `A=5300, D=2.6, R=1`일 때 **진입 2,038.46 USDT / 손절 손실 53.00 USDT**가 표시된다.
- [ ] 진입 금액 복사 버튼이 동작한다.
- [ ] 레버리지 및 증거금에 관한 입력·결과가 전혀 없다.
- [ ] 잘못된 값·공란·0으로 나누기 상황을 안전하게 처리한다.
- [ ] 새로고침과 앱 재실행 후 저장된 입력값이 복원된다.
- [ ] Windows PC와 Android 화면에서 사용하기 편리하다.
- [ ] GitHub Pages의 **저장소 하위 경로**에서 정적 리소스와 PWA가 모두 정상 동작한다.
- [ ] Windows/Android에서 PWA 설치가 가능하다(지원 브라우저 기준).
- [ ] 최초 정상 로드 및 서비스 워커 활성화 이후 인터넷 연결을 끊고 다시 실행해도 계산이 된다.
- [ ] 테스트 코드와 README가 포함되어 있다.
- [ ] 백엔드, 데이터베이스, 로그인, 외부 API가 없다.

## 11. 구현에서 제외할 사항(명시적 금지)

다음은 **이번 작업에 포함하지 않는다.** 후속 버전 제안이나 미리 구현한 확장 코드도 넣지 않는다.

- Firebase, Supabase 등 클라우드 저장·동기화
- 회원가입·로그인·계정관리
- 자체 서버 또는 유료 호스팅
- 레버리지·증거금·청산가 계산
- 거래소 API 연결, 잔고 자동조회, 주문 실행
- 진입가/손절가 가격 입력과 가격 차이 자동 계산
- 거래 기록, 차트, 알림, 수익률 분석
- 별도 네이티브 Windows 실행 파일이나 APK 빌드
